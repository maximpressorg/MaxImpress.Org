## Verification protocol for future customer reviews
1. Obtain original customer-authored review or link to the independent review on the actual provider platform.
2. Confirm reviewer identity / service purchase without publishing private contact data.
3. Preserve original wording, date and numeric rating; obtain permission if republishing.
4. Use Google/Trustpilot badges only when the review actually originated there and the source link can be opened.
5. Label direct website submissions "Client-submitted" after confirmation, never "Google verified".

## Result evidence protocol
1. Capture initial analytics and final analytics for identical platform and defined periods.
2. Preserve the source dashboard, dates, audience size and metric definitions.
3. Specify which deliverables MaxImpress handled; don't infer causation from an account's public metrics.
4. Get client permission to feature the account or share private screenshots.
5. Only publish results as verified when supporting evidence is reviewed and linked.

## SEO scope
- Unique existing HTML titles and descriptions checked; missing descriptions supplied.
- Open Graph metadata supplied where missing; image alt and lazy-load checked.
- Canonical URLs and final sitemap.xml require confirmed deployed hostname (do not guess).
- Real ranking, impressions, organic traffic, indexing status and Core Web Vitals require the live verified deployment and Search Console / analytics access. Static HTML cannot measure them.
- Google does not allow fabricated or undisclosed incentivized review structured data; no fake review schema added.

## Caveat
- Existing illustrative reviews and previous portfolio outcome claims in inherited website files have not been audited independently. They should not be presented as independently verified.
